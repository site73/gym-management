# 模块接口契约

> 所属阶段：第八阶段（系统结构与代码结构设计）
> 原则：**跨模块访问必须经过接口契约，不允许直接读取对方模块的数据表**；契约变更须版本化并与测试同步。

## 一、契约总览

| 提供方模块 | 契约接口 | 主要调用方 | 状态 |
|---|---|---|---|
| system | `SystemFacade` | 全部模块 | 规划 |
| membership | `MembershipFacade` | booking / payment / warning / report | 规划 |
| course | `CourseFacade` | booking / report | 规划 |
| booking | `BookingFacade` | payment / warning / report | **已建立** |
| payment | `PaymentFacade` | membership（订单驱动会籍） | 规划 |
| assessment | `AssessmentFacade` | report | 规划 |
| warning | `WarningFacade` | report | 规划 |
| equipment | `EquipmentFacade` | report | 规划 |
| report | `ReportFacade` | 管理后台 | 规划 |
| shared | `RuleEngine` | 全部模块 | **已建立** |

## 三、领域事件契约（解耦通信）

事件由领域层发布、跨模块订阅，避免直接调用造成的强耦合：

| 事件 | 发布方 | 订阅方 | 用途 |
|---|---|---|---|
| `MembershipActivatedEvent` | membership | payment、report | 办卡/续费生效 |
| `BookingCheckedInEvent` | booking | payment、warning | 触发课消核销、刷新活跃度 |
| `BookingNoShowEvent` | booking | warning、report | 累计爽约、风险评分 |
| `CourseFinishedEvent` | course | payment | 结课触发核销 |
| `PaymentSucceededEvent` | payment | membership | 订单驱动会籍续期 |
| `WarningCreatedEvent` | warning | report、notification | 生成预警任务与提醒 |

**约定**：事件为**幂等消费**（订阅方按业务唯一键去重）；事件结构变更视为契约变更，须版本化。

## 四、禁止事项（红线）

1. ❌ 其他模块**不得**依赖 `com.gym.<模块>.internal` 下的类；
2. ❌ **不得**直接查询/更新对方模块拥有的数据表（如 booking 不得读写 course 表，只能走 `CourseFacade`）；
3. ❌ **不得**在契约中暴露领域实体或 JPA Entity（只允许 DTO）；
4. ❌ **不得**在跨模块调用中开启跨模块写事务（须以事件最终一致或应用层编排）；
5. ❌ **不得**硬编码规则阈值（统一经 `RuleEngine` 读 `rule_config`）。

以上由 ArchUnit 守卫测试部分固化，其余在代码评审中把关。

## 五、契约变更流程

1. **新增**方法：向后兼容，随功能提交，同步补充 `.feature` 测试场景。
2. **修改/删除**方法：须评估所有调用方，形成变更说明，**升级契约版本**（如 `BookingFacade#countNoShow` → v2 新方法，旧方法标记 `@Deprecated` 并约定下线时间）。
3. 契约文件（OpenAPI）与 `.feature`、代码**同版本库、同版本号**管理；关键测试未通过不得进入试点或正式部署。
4. 契约变更须同步更新本文件与《外部接口设计说明》（涉及外部接口时）。
