# 业务数据初始化与迁移方案

> 所属阶段：第七阶段（数据库、外部接口、业务数据初始化与部署方案设计）
> 说明：新系统上线前，不仅要建表和部署，更要解决"现实业务数据如何进入系统"。本方案在全局业务基线确认阶段即提前识别，现正式形成。

## 一、前期识别清单

| 识别项 | 本店情况 | 处理方式 |
|---|---|---|
| 哪些基础数据必须准备 | 角色、字典（状态/类型）、课程目录、器材分类、规则参数 | 由种子脚本初始化（`db/seed/R__seed_base_data.sql`） |
| 哪些历史业务数据必须迁移 | 有效会员档案、会籍起止与剩余次数、未结清订单、私教课包余次 | 迁移（见第（2）部分） |
| 哪些数据只需归档 | 已过期会籍的历史记录、往年纸质考勤、已关闭投诉记录 | 归档留存，不迁入系统 |
| 哪些进行中业务对象需在切换日继续处理 | 切换日仍在有效期内的会籍、未核销完的私教课包、待处理投诉 | 建"切换日快照"清单，逐条导入 |
| 哪些旧状态需映射到新状态机 | 旧台账的口语化状态（正常/停卡/到期未续等） | 见第（3）部分映射表 |
| 数据来源在哪里 | 会员 Excel 台账、收费 Excel、体测纸质表、微信群排课记录 | 逐一收集并确认版本 |
| 数据质量是否满足迁移要求 | 手机号缺失/重复、会籍起止日期不全、姓名不规范 | 迁移前做质量校验与补录清单 |
| 是否涉及敏感信息/合规 | 手机号、健康体测数据 | 最小化采集、加密存储、脱敏展示、授权明确 |

## 二、方案内容

### （1）基础数据初始化范围

- **组织与账号**：门店信息、系统用户（店长/会籍/私教/财务/管理员）与角色权限。
- **字典**：会员状态、预约状态、课程状态、订单状态、工单状态、课程目录、器材分类。
- **业务规则参数**：SYS-R1–R10 默认值（N=3、D=7、T=0.6、时间窗 30 天/4 周、提成比例 20%）。
- **课程目录**：团课/私教课名与默认时长、容量。
- **器材台账**：资产编号、名称、分类、位置。
- **交付方式**：`R__seed_base_data.sql`（幂等，可重复执行），上线前由店长确认参数。

### （2）历史业务数据迁移范围

| 数据类别 | 是否迁移 | 关键字段 | 来源 |
|---|---|---|---|
| 有效会员档案 | 迁移 | 姓名、手机号、性别、生日、来源 | 会员 Excel |
| 会籍合同（有效/冻结） | 迁移 | 类型、起止日期、状态、剩余次数 | 会籍 Excel |
| 私教课包余次 | 迁移 | 会员、剩余次数、有效期 | 私教销售记录 |
| 未结清订单 | 迁移 | 金额、状态 | 收费台账 |
| 历史订单/支付记录 | **归档** | — | 收费台账（只归档不迁入） |
| 历史体测纸质表 | 选择性迁移 | 最近 1 次体测数据 | 纸质体测表 |
| 历年考勤/签到 | 归档 | — | 微信群记录 |
| 已关闭投诉 | 归档 | — | 纸质/口头记录 |

### （3）存量对象状态映射

| 对象 | 旧台账取值（示例） | 新系统状态 |
|---|---|---|
| 会员/会籍 | 正常 / 在用 | `active` |
| 会员/会籍 | 停卡 / 请假 | `frozen` |
| 会员/会籍 | 到期未续 / 作废 | `expired` |
| 会员/会籍 | 已退卡 / 不再来 | `lost` |
| 私教课包 | 还剩 N 次 | `remaining_times = N`（无旧状态，直接迁移余次） |
| 订单 | 已收款 | `paid` |
| 订单 | 未收款 / 挂账 | `pending` |

映射规则须在迁移演练中抽检确认，**不允许出现无法映射的取值**；否则先补录再迁移。

### （4）数据迁移与切换方式

- **迁移方式**：首轮为**全量迁移**（数据量小，单店 ≤3000 会员）；切换后如有增量（切换日当天的办卡/签到），采用**增量补录**方式补齐。
- **切换日安排**：
  1. T-7 完成数据收集与质量校验，输出补录清单；
  2. T-3 预演迁移（在试点环境执行全流程 + 核对）；
  3. T-1 冻结旧台账写入，导出最终快照；
  4. T 日：停止旧方式登记 → 执行全量迁移 → 核对 → 开放系统使用；切换日现场安排 1 人值守答疑。
  5. T+3 观察期，处理遗漏与差异。
- **迁移演练**：至少一次完整预演，记录耗时、失败条目与修正动作。
- **核对方式**：按类别核对总量与抽样明细——会员数、有效会籍数、课包余次合计、未结清订单金额；抽样 ≥10% 逐条比对；核对表由店长签字。
- **回滚预案**：
  - 迁移失败或核对不通过 → **保留旧台账继续使用**，系统暂不切换（新系统仅做只读演示）；
  - 已切换但发现严重问题时 → 停止对外使用新系统，回滚数据库到迁移前备份（见《部署方案设计》备份策略），并恢复旧登记方式；
  - 回滚决策点：切换后 48 小时内，若核心数据（会籍/课包）错误率 > 1%，即触发回滚评估。

## 三、合规与安全

- 手机号等个人信息**加密存储、脱敏展示**；体测健康数据仅授权角色可见。
- 迁移过程使用加密传输与临时中间库；迁移完成后**清理中间文件**。
- 迁移人员签署保密承诺；迁移日志留痕（谁、何时、迁移了哪些批次）。

## 四、交付物与责任人

| 交付物 | 责任人 | 时间 |
|---|---|---|
| 数据收集与补录清单 | 会籍顾问 | T-7 |
| 迁移脚本与核对表 | 技术负责人 | T-3 |
| 迁移演练报告 | 技术负责人 + 店长 | T-3 |
| 切换日快照与核对签字 | 店长 | T 日 |
| 回滚预案确认 | 店长 + 技术负责人 | T-1 |
