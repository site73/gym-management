# 外部接口设计说明

> 所属阶段：第七阶段（数据库、外部接口、业务数据初始化与部署方案设计）
> 上游依据：《接口契约初步清单》（第四阶段）、外部依赖识别
> 原则：外部接口基于业务活动中的**真实外部依赖**设计；契约版本化管理，与测试用例同步；原型阶段以 Mock 先行验证。

## 一、外部依赖来源

| 业务活动 | 外部依赖 | 必要性 |
|---|---|---|
| 会员登录（A1 前置） | 微信小程序登录 | 必需 |
| 支付（A1/A6 课包） | 微信支付 | 必需 |
| 到期提醒（SYS-R6） | 微信订阅消息 / 短信 | 必需（二选一，Q10 待定） |
| 爽约提醒（SYS-R8） | 微信订阅消息 | 必需 |
| 体测/健康数据 | 无外部依赖（本地录入） | — |
| 地图导航/实名认证/电子签章 | 本轮回合不需要 | 范围外（见基线） |

## 二、接口明细

### EXT1 微信登录（code2Session）

- **用途**：小程序端会员登录，换取 openid/session_key。
- **协议与契约**：HTTPS `GET /sns/jscode2session`；契约字段 appid/secret/js_code → openid/session_key。
- **鉴权**：AppID + AppSecret（仅服务端持有）。
- **调用时机**：会员首次进入小程序或登录态过期时。
- **超时与重试**：超时 3s，失败重试 2 次（指数退避）。
- **异常与降级**：失败返回"登录失败，请重试"；会员仍可用前台代约/代签旁路。

### EXT2 微信支付（下单）

- **用途**：会籍与私教课包支付。
- **协议与契约**：HTTPS `POST /v3/pay/transactions/jsapi`；金额单位"分"。
- **鉴权**：商户私钥签名（APIv3 证书）+ 平台证书验签。
- **调用时机**：会员提交订单后。
- **超时与重试**：超时 5s，**下单不自动重试**（避免重复单），失败提示用户重试。
- **异常与降级**：下单失败不改动会籍；支持现金/前台代收作为降级渠道。

### EXT3 微信支付回调（支付结果通知）

- **用途**：接收支付结果，驱动订单与会籍变更。
- **协议与契约**：HTTPS 回调 → 必须**验签 + 解密**，返回 200 才视为成功。
- **幂等**：以 `out_trade_no` 唯一键去重，重复回调不重复续期（对齐 REQ-B5-004）。
- **调用时机**：支付成功后微信主动通知。
- **超时与重试**：微信按策略重试；本系统处理须在 5s 内返回。
- **异常与降级**：**金额不符或验签失败 → 订单置 `abnormal` + 告警 + 会籍不变更**；提供"主动查单"补偿任务定时核对。

### EXT4 微信订阅消息（提醒）

- **用途**：续费提醒（SYS-R6）、爽约提醒（SYS-R8）、预警通知。
- **协议与契约**：HTTPS `POST /cgi-bin/message/subscribe/send`。
- **鉴权**：access_token（带缓存，提前 5 分钟刷新）。
- **调用时机**：定时任务或事件触发（如每日扫描到期会员）。
- **超时与重试**：超时 3s，失败重试 3 次并记录 `notification.retry_count`。
- **异常与降级**：订阅消息需用户授权，未授权 → 降级为短信或 APP 内消息（Q10）。

### EXT5 短信服务（兜底提醒）

- **用途**：订阅消息不可用时的兜底通道。
- **协议与契约**：HTTPS，模板化发送（签名 + 模板 ID）。
- **鉴权**：AccessKey（服务端持有，不入库明文）。
- **调用时机**：订阅消息失败或用户未授权。
- **超时与重试**：超时 5s，重试 2 次。
- **异常与降级**：短信也失败则仅记录，转人工跟进（不阻断主流程）；需成本评估（Q10）。

## 三、契约版本化与测试同步

- 协议以 **OpenAPI 3.0** 描述，文件入库统一管理（`contracts/`），版本号随接口变更递增。
- 接口契约与行为驱动测试（第五阶段 `.feature`）**同版本管理**：接口变更必须同步更新测试场景，关键测试未通过不得进入试点或正式部署。
- 外部接口在原型阶段以 **Mock 先行**（见第六阶段 `mock/mock-api.md`）；对接真实环境前先跑沙箱。
