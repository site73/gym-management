# 09 · 经验蒸馏方法（元方法）

## 适用场景

- 一个项目告一段落，需要把经验变成可复用资产
- 同样的问题反复出现，需要机制化避免
- 要把"某项目的做法"提炼成"任何项目都能用的规则"
- 给 Skill 补充新案例或新规则

## 核心原则

1. **只从真实事故提炼**：没有发生过的假设，不进规则库。
2. **区分"事实 / 方法 / 偏好"**：三者混写会让 Skill 无法迁移。
3. **可判定**：每条经验都要能回答"怎么算做到 / 怎么算没做到"。
4. **保留反例**：只写"应该怎样"的价值远低于"没这样做时出了什么事"。

## 执行步骤

### 步骤 1 · 收集素材
| 来源 | 提取什么 |
|---|---|
| 对话记录 | 用户反复强调/纠正的点、被拒绝的方案、临时追加的要求 |
| 代码与提交 | 反复修改的文件、回滚、紧急修复 |
| 缺陷表 | 现象、级别、根因、修复方式 |
| 测试报告 | 失败用例、偶发问题、覆盖缺口 |
| 文档 | 决策理由（ADR）、被推翻的假设 |
| 环境记录 | 启动失败、端口冲突、编码/代理问题 |

**验收**：素材带出处（提交号、文档章节、对话轮次），可回溯。

### 步骤 2 · 按统一模板拆解
每条经验写成五段：

```
现象：用户/系统看到了什么（可观察）
根因：技术或流程上的真实原因（不是"疏忽"）
处理：当时怎么解决的（含关键命令/代码位置）
预防：怎么让它不再发生（机制，不是"下次注意"）
迁移：这条在别的项目成立吗？条件是什么？
```

**验收**：五段齐全；"预防"必须是机制（测试/校验/约束），不是态度。

### 步骤 3 · 判定通用 / 专属
用四个问题判定：

| 问题 | 若答"是" | 若答"否" |
|---|---|---|
| 换个业务领域还成立吗？ | 偏通用 | 偏专属 |
| 换个技术栈还成立吗？ | 偏通用（方法层） | 偏专属（实现层） |
| 换个团队规模还成立吗？ | 偏通用 | 需加适用条件 |
| 去掉项目名后句子还通顺吗？ | 偏通用 | 专属 |

**归类规则**：
- 四问全"是" → 进 `references/`（方法）
- 前两问"是"、后两问"否" → 进 `references/` 但标注适用条件
- 含具体技术/路径/账号/业务名词 → 进 `examples/`（案例）

**验收**：`references/` 中不出现项目名、具体路径、真实账号。

### 步骤 4 · 写进对应层
| 内容 | 放哪 | 要求 |
|---|---|---|
| 可复用步骤与验收 | `references/NN-*.md` | 场景 + 步骤 + 验收 + 反例 |
| 能直接填的表 | `templates/` | 占位符清晰，示例可删 |
| 真实事故全过程 | `examples/` | 含项目背景、时间线、数据 |
| 一句话硬约束 | `SKILL.md` §4 | 必须有事故支撑，编号唯一 |

**验收**：同一内容只存在一处，其它位置用引用。

### 步骤 5 · 去重与冲突
1. 新规则与旧规则重复 → 合并，保留更可判定的表述。
2. 新规则与旧规则冲突 → 不直接覆盖，标 `Deprecated` 并写"为什么被推翻"。
3. 规则数量控制：`SKILL.md` §4 保持 10 条以内，多了说明抽象层级不对。

**验收**：规则库无同义重复；每条有编号且被引用过。

### 步骤 6 · 验证可迁移性
用"陌生人测试"：
1. 找一个没参与过该项目的人（或新会话），只给 Skill 不给背景。
2. 让他按 Skill 做一个类似任务。
3. 记录卡住的地方 → 说明该处缺步骤或缺判据。

**验收**：卡点被补齐，或标注"待验证"。

## 反模式（明确禁止）

| 反模式 | 表现 | 为什么错 |
|---|---|---|
| 把实现写成规则 | "用 Spring Boot 的 @Transactional 保证一致性" | 换栈即失效 |
| 把偏好写成规则 | "文档必须放 E 盘" | 是个人习惯，非工程约束 |
| 编造历史 | 写一个没发生过的"事故"来支撑规则 | 无法回溯，污染经验库 |
| 只写结论 | "要注意数据一致性" | 不可执行 |
| 规则无限膨胀 | `SKILL.md` 塞 50 条 | 上下文过载，等于没有 |

## 沉淀后的维护

- 每次新事故 → 先查是否已有规则；有则补案例，无则新增。
- 版本号随规则变化递增；破坏性调整写迁移说明。
- 定期（如每季度）回看 `待验证` 条目，能验证的转正，不能的删除。

## 验收清单

- [ ] 每条经验有五段拆解
- [ ] 已判定通用/专属并放入正确目录
- [ ] `references/` 无项目专有名词
- [ ] 每条规则有事故支撑与编号
- [ ] 无重复规则、无编造内容
- [ ] 做过陌生人测试或有待验证标注

## 待验证

- "陌生人测试"的成本较高，小团队可退化为"新会话复述测试"。
