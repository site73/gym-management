# 06 · 质量控制

## 适用场景

- 需要设计测试策略、补齐测试覆盖
- 判断"能不能交付"
- 做安全与边界探测
- 建立回归防线

## 核心原则

1. **分层防御**：不同层解决不同问题，不能只靠一种测试。
2. **测试要能挡住真实事故**：每条用例对应一个曾经或可能发生的问题。
3. **可复现**：一条命令跑完，自带数据准备与复位。
4. **覆盖要有缺口清单**：不追求数字好看，如实标注未覆盖项。

## 执行步骤

### 步骤 1 · 设计测试矩阵
按层划分，每层职责单一：

| 层 | 解决什么 | 不解决什么 |
|---|---|---|
| 单元 | 规则、算法、状态迁移 | 集成问题 |
| 架构 | 依赖方向、分层约束 | 业务正确性 |
| 契约 | 接口形状、字段、错误码 | 业务规则 |
| 集成 | 真实 HTTP 全链路、权限 | 页面交互 |
| 前端静态 | 未定义函数、元素缺失、接口不存在 | 运行时行为 |
| 真实浏览器 | 点击有响应、渲染正确、无 JS 错误 | 性能 |
| 冒烟 | 核心路径可用 | 边界 |

**验收**：每层有明确职责，不重复也不遗漏。

### 步骤 2 · 建立不变量用例
对关键约束写"全量校验"，而不是抽查：
- 计数 = 明细条数（逐条遍历）
- 状态机无非法迁移
- 越权一律 403、未登录 401
- 敏感字段不出现在响应里

**验收**：不变量用例能在数据异常时立刻报警。

### 步骤 3 · 异常与边界用例
必测清单：
1. 空值 / 极值 / 超长 / 非法类型
2. 重复提交 / 并发
3. 越权（改 ID、改 scope、伪造归属）
4. 上游失败 / 超时
5. 满员 / 余额为 0 / 已取消等边界状态

**验收**：每条都有明确期望码与提示。

### 步骤 4 · 安全探测
在功能测试之外单独做一轮：
- 认证绕过（无 token、篡改 token、过期 token）
- 越权（水平/垂直）
- 注入（SQL/命令/模板）
- 输出转义（存储型 XSS）
- 回调伪造（无签名/弱校验）
- 敏感信息泄露（密码、密钥、内部路径）

**验收**：每项给出"安全/风险"结论，风险项标注级别与修复建议。

### 步骤 5 · 数据准备与隔离
- 每个用例自带前置数据，不依赖其他用例。
- 用唯一后缀（时间戳）避免多次运行冲突。
- 测试开始前复位，结束后不污染环境。

**验收**：单独跑任一用例都能通过。

### 步骤 6 · 出报告
报告包含：执行环境、用例总数与通过数、失败项根因、未覆盖项与原因、复跑命令。

**验收**：他人按报告能原样复现结果。

## 验收清单

- [ ] 测试矩阵分层清晰
- [ ] 关键不变量有全量校验
- [ ] 异常/边界/安全用例齐备
- [ ] 用例相互独立、可单跑
- [ ] 报告含复跑命令与缺口说明
- [ ] 全量一次通过或有明确解释

## 常见偏差

| 偏差 | 后果 | 纠正 |
|---|---|---|
| 只做接口测试 | 页面点了没反应照样上线 | 加静态检查 + 浏览器测试 |
| 用例互相依赖 | 顺序一变就挂 | 自带数据 + 复位 |
| 只测正常路径 | 异常全漏 | 强制清单 |
| 追求覆盖率数字 | 覆盖了但没断言 | 看断言质量 |

## 待验证

- 真实浏览器测试的稳定性依赖环境（浏览器版本、等待策略），需按项目固化。
