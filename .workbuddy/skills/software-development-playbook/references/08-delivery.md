# 08 · 交付与部署

## 适用场景

- 准备发版、打包、上线
- 需要交付文档与演示材料
- 需要把成果提交到代码仓库
- 需要复盘交付质量

## 核心原则

1. **可复现优先于自动化**：先保证"任何人按文档能跑起来"，再谈流水线。
2. **版本可追溯**：每次交付有标签、有变更说明、有对应测试结果。
3. **交付物分层**：运行物（包/镜像）+ 说明（README/手册）+ 证据（测试报告）。
4. **对外产物先脱敏**：密钥、真实姓名、内部地址一律清除。

## 执行步骤

### 步骤 1 · 交付前检查（门禁）
逐项确认：

| 项 | 判据 |
|---|---|
| 构建 | 干净环境可构建成功 |
| 启动 | 冷启动成功，端口/依赖明确 |
| 配置 | 配置外置，无硬编码密钥 |
| 数据 | 迁移脚本可从空库建起 |
| 测试 | 全量通过，报告可查 |
| 文档 | 运行手册、账号表、接口说明齐备 |
| 元数据 | 提交作者、署名、License 符合约定 |

**验收**：全部打勾才进入打包。

### 步骤 2 · 版本与变更说明
1. 语义化版本（主.次.补丁）。
2. 打附注标签，写清本次范围与验收口径。
3. 变更说明分三类：新增 / 修复 / 破坏性变更。

**验收**：任一版本能查到"改了什么、怎么验证"。

### 步骤 2.5 · 业务数据初始化

结构迁移只解决"表建好了"，业务上线还需要**初始数据**（期初库存、基础档案、规则参数、账号与权限）。

| 类型 | 内容 | 校验 |
|---|---|---|
| 基础档案 | 分类、单位、仓库/门店、供应商 | 唯一性、必填项 |
| 期初数据 | 期初库存/余额/积分 | 与业务方签字确认的台账逐条核对 |
| 规则参数 | 阈值、费率、开关 | 默认值可查、可改、变更留痕 |
| 账号权限 | 角色、初始账号 | 最小权限；初始密码强制修改 |

**要点**：
- 期初数据必须有**核对机制**（导入后跑一次对账，与源台账比对）。
- 导入脚本要可重复执行（幂等），避免重跑产生重复数据。
- 初始数据要留版本，出问题能回到导入前。

**验收**：导入后对账一致；重跑不产生重复；有回退方案。

### 步骤 3 · 打包与部署
- 产物命名含版本号。
- 部署步骤写成脚本或清单，不靠口口相传。
- 首次部署与升级部署分开写（升级要考虑数据迁移）。

**验收**：按清单在干净机器上部署成功。

### 步骤 4 · 交付文档
最小集合：
1. `README`：是什么、怎么跑、账号、目录结构
2. 运行手册：启动/停止/排障/数据复位
3. 测试报告：层、数量、结果、复跑命令
4. 变更记录：版本与范围

**验收**：文档中的命令可直接复制执行。

### 步骤 5 · 演示材料
- PPT：结论先行，每页一个观点，附来源。
- 讲稿：逐页台词 + 演示步骤 + 时间分配 + 删减方案。
- 演示脚本：按顺序列出操作与预期现象。

**验收**：按讲稿能在目标时长内讲完，且演示路径不依赖临场发挥。

### 步骤 6 · 提交与发布
1. 提交前跑全量（总控 R10）。
2. 检查提交元数据（总控 R8）。
3. 推送后确认远程指向正确提交。
4. 打标签并推送。

**验收**：远程与本地一致；标签指向验收通过的提交。

## 验收清单

- [ ] 干净环境可构建、可启动
- [ ] 配置无硬编码密钥
- [ ] 空库可迁移到最新结构
- [ ] 全量测试通过
- [ ] 版本标签与变更说明齐备
- [ ] 文档命令可执行
- [ ] 提交元数据合规
- [ ] 远程已确认

## 常见偏差

| 偏差 | 后果 | 纠正 |
|---|---|---|
| 只在开发机验证 | 换机就崩 | 干净环境验证 |
| 密钥写进配置 | 泄露 | 外置 + 脱敏检查 |
| 文档写"按需配置" | 实际没人配得对 | 给出完整示例 |
| 只推 commit 不打标签 | 无法定位交付点 | 打附注标签 |
| 推送失败不确认 | 以为传了其实没传 | 推送后核对远程 |
