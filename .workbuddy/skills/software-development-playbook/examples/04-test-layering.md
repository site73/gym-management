# 案例 04 · 七层测试是怎么长出来的（388 项）

> **来源项目**：健身房运营管理系统
> **对应规则**：总控 R3（缺陷必须带回归用例）、R10（收敛前跑全量）
> **性质**：测试体系演进过程，含每一次加层的触发事故

## 背景

最终形态是 7 层、388 项自动化检查：

| 层 | 数量 | 触发它诞生的问题 |
|---|---|---|
| 单元 | 67 | 业务规则需要快速验证 |
| 架构守卫 | 3 | 模块边界被悄悄绕过 |
| 行为驱动（Cucumber） | 18 | 需求要能"可执行" |
| 集成（真实 HTTP） | 139 | 单元测试测不出权限与事务 |
| 前端静态检查 | 6 | 按钮点了没反应 |
| 真实浏览器 | 113 | 静态检查测不出运行时渲染 |
| 二维码结构校验 | 5 | 生成的码扫不出来 |
| 参考实现 BDD + 冒烟 | 18 + 18 | 需要一份独立实现做对照 |

**关键点：每一层都不是"最佳实践清单"里抄来的，而是被某次事故逼出来的。**

## 逐层由来

### 单元测试：规则要能秒级回归
爽约惩罚、容量校验、状态迁移这类纯逻辑，用单元测试最快。
一次改阈值（N=3 → 5）时，只有单元测试能在 1 秒内告诉你影响了哪些场景。

### 架构守卫：边界靠机制，不靠自觉
项目初期出现过"订单模块直接 import 会员模块的内部实体"，改表时连锁崩溃。
引入 ArchUnit 后，三条规则被固化：
1. Controller 不得直连 Repository
2. 跨模块只能依赖对方 api 包
3. shared 不得反向依赖业务模块

**价值**：新人第一次违反就会红，不需要靠 code review 抓。

### 集成测试：单元测不出的事务与权限
单元测试全绿，但"会员调用店长接口返回 200"——因为权限校验在 Controller 层，
单元测试直接调 Service 绕过了它。

集成测试走真实 HTTP + 真实会话，才能验证：
- 401/403 的实际返回
- 事务回滚是否彻底
- 序列化后的字段是否泄露

### 前端静态检查：为了"点了没反应"
真实事故：`onclick="doCancel(${b.id})"` 中 ID 没加引号，被当成变量，
点击抛 `ReferenceError` 且被静默吞掉。用户看到的是"按钮没反应"。
单元测试和接口测试都发现不了。

于是加了 6 条静态检查：
1. 内联脚本语法合法
2. onclick 参数已加引号
3. onclick 调用的函数已定义
4. `$('id')` 引用的元素存在
5. 前端调用的接口后端都存在
6. 引用的全局常量都已声明

第 6 条是又一次事故逼出来的：变量名写错（`VENUE_BOOKING_CN` vs `VENUE_STATUS_CN`），
整段渲染中断、页面停在"加载中…"，而前 5 条都查不出来。

### 真实浏览器：静态检查测不出渲染
静态检查能确认"函数存在"，但不能确认"点了真的有反应"。
用 Playwright + 无头 Edge 真实点击，验证：
- 弹窗真的弹出
- 列表真的渲染
- 控制台无 JS 错误、无 5xx

**代价**：慢（分钟级）、偶发不稳定。处理办法是"等待具体文本变化"而不是死等固定时长。

### 二维码校验：能生成 ≠ 能扫
签到二维码由前端内嵌生成器产出。为了证明它"真的能扫"，
写了一个反解脚本：把生成的图反向解析回原文，比对是否一致。
5 个用例覆盖不同版本（v1/v2/v4/v7）与不同长度内容。

## 每次加层的共同模式

```
出现一个"现有测试抓不到"的事故
  → 定位到"哪一类信息现有层看不见"
  → 加一层只解决这一类问题
  → 把这层加进全量执行脚本
```

**没有为了覆盖率加层，也没有为了数字好看写空断言。**

## 测试数据的教训

- 早期用例互相依赖，单独跑就挂。改为每个用例自带前置数据 + 唯一后缀（时间戳）。
- 集成/浏览器脚本开头统一调一次"数据复位"接口，避免被上一个脚本的状态影响。
- 偶然发现"跑三次挂一次"，根因是浏览器测试改了数据、集成测试接着跑。
  → 每个脚本自己复位，不依赖执行顺序。

## 可迁移结论

1. **测试层由事故驱动**，不是由最佳实践清单驱动。每加一层，说清"它解决哪类现有层看不见的问题"。
2. **静态检查是性价比最高的一层**：不依赖运行环境、秒级、能挡住一整类"点了没反应"。
3. **真实浏览器测试必须有稳定的等待策略**，否则会变成"重启一下就好了"的噪音源。
4. **用例必须自带数据**，任何依赖执行顺序的测试都是定时炸弹。
5. **不变量用例要全量遍历**（见案例 01），抽查会漏。
6. 报告要写"未覆盖项与原因"，不要用总数掩盖缺口。
