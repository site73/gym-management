# 案例 02 · 环境踩坑合集（"不是代码问题"的六次误判）

> **来源项目**：健身房运营管理系统（Windows + E 盘便携环境）
> **对应规则**：总控 R6（环境事实先验证再归因）
> **性质**：真实问题，均已沉淀为项目 Skill 的排障表

## 背景

项目在 Windows 上使用便携版 JDK/Maven/MySQL/Node，每次新会话重启环境都会遇到
"看起来像代码 bug、实际是环境"的问题。以下六条是实际发生过的。

---

## 坑 1 · 端口被环境变量劫持

**现象**：`java -jar app.jar` 启动报
`Web server failed to start. Port 2798 was already in use`。
但配置文件里明明写的 `server.port: 8080`。

**误判**：以为配置文件没生效、或端口被别的程序占用。

**根因**：环境里存在 `SERVER__PORT=2798`（双下划线），Spring Boot 的 relaxed binding
把它解析成 `server.port`，优先级高于配置文件。

**处理**：启动命令显式加 `--server.port=8080`（命令行参数优先级最高），必要时 `unset SERVER__PORT`。

**迁移**：任何"配置明明对但就是不生效"的情况，先查环境变量与命令行覆盖链，
再怀疑配置文件解析。优先级顺序要写进运行手册。

---

## 坑 2 · 离线 Maven 报 "present but unavailable"

**现象**：`mvn -o` 报某依赖 `is present in the local repository but could not be resolved`。

**误判**：以为本地仓库缺包。

**根因**：本地仓库（`E:/dev/m2repo`）里的 `_remote.repositories` 记录了来源仓库 id，
必须用与当初下载时相同的 settings（镜像 id 匹配）才能解析；只用 `-o` 不带 settings 会失败。

**处理**：始终带 `-s <settings.xml>`，且 settings 里的镜像 id 与仓库元数据一致。

**迁移**：离线构建失败先看"仓库元数据 vs settings 镜像 id"，不是先删仓库重下。

---

## 坑 3 · 代理端口漂移导致"接口全挂"

**现象**：脚本请求 `127.0.0.1:8080` 报连接失败或 502；`curl` 也不通。

**误判**：以为后端没起来。

**根因**：环境注入了 `HTTP_PROXY/HTTPS_PROXY`，代理端口在不同会话间会变
（观察到 2467、7237 等），且代理本身可能返回 502。本地回环请求被代理劫持。

**处理**：
- 本地请求加 `--noproxy '*'`（curl）或在客户端显式禁用代理；
- git 推送用 `git -c http.proxy= -c https.proxy= push` 清空代理走直连。

**迁移**：凡是"本地服务明明在监听，客户端却连不上"，先查代理与环境变量。

---

## 坑 4 · 数据库迁移脚本不会重复执行

**现象**：演示课程日期越来越旧，某天打开"本周课表"全是空的。
会员选课也失败，提示课程已开始。

**误判**：以为课表接口写错了。

**根因**：种子数据用 `CURDATE()` 落库，但 Flyway 的 `R__` 可重复脚本
**只在内容变化时重跑**，不会每次启动都执行。所以日期一直停在首次执行那天。

**处理**：加"演示数据对齐器"，在启动与数据重置后把演示课程/场地预约
对齐到本周剩余的未来日期；系统内已有本周真实数据时不介入。

**迁移**：任何"用当前时间生成的种子数据"都会漂移。要么每次启动校正，
要么用相对时间在查询时计算，不要指望迁移脚本重跑。

---

## 坑 5 · 乱码与字体（工具链层面）

**现象**：PlantUML 生成的中文图全是乱码/方框。

**根因**：JVM 默认编码为 GBK，而源文件是 UTF-8。

**处理**：`java -Dfile.encoding=UTF-8 -jar plantuml.jar -charset UTF-8 ...`，
并显式指定中文字体（如 Microsoft YaHei）。

**迁移**：跨语言/跨编码的工具调用，编码参数要显式给，不能依赖默认值。

---

## 坑 6 · 后台进程随启动器退出被回收

**现象**：用某个 `start-system.js` 拉起 MySQL 和后端，脚本一结束服务就没了。

**根因**：子进程绑定在启动器的进程组上，父进程退出后被一起回收。

**处理**：改用宿主提供的"后台任务"机制直接运行 `mysqld`/`java`，日志重定向到文件。

**迁移**：常驻服务不要挂在短命脚本下；启动方式要能在"脚本退出后继续存活"。

---

## 可迁移结论

1. **启动失败先列事实**：端口、进程、环境变量、日志首条错误，四项核对完再改代码。
2. **环境问题要写进运行手册**，而不是每次重新排查。判断标准：这个问题会不会在换机器/换会话后重现？会 → 写手册。
3. **优先用"显式参数"压过"隐式环境"**：命令行 > 环境变量 > 配置文件，出问题时用高优先级显式覆盖。
4. **区分"代码缺陷"与"环境约束"**，汇报时说清是哪一类，避免团队在错误方向上花时间。
