## 二、Mock 接口

| 接口 | 方法 | 用途 | Mock 行为 | 关联需求 |
|---|---|---|---|---|
| /auth/login | POST | 会员登录 | 直接返回预设会员，跳过微信 code2Session | REQ-M0-001（EXT1 替代） |
| /courses | GET | 课程列表 | 返回 3 门课程及剩余名额 | REQ-B3-002 |
| /bookings | POST | 约课 | 依次执行 SYS-R1→R4→R3 校验，成功则名额-1 | REQ-B4-001 |
| /bookings/{id}/checkin | POST | 签到 | 状态改"已签到" | REQ-B4-002 |
| /bookings/{id}/cancel | POST | 取消 | 状态"取消"，名额+1 | SYS-R3 |
| /bookings/{id}/timeout | POST | 模拟超时 | 状态"爽约"，爽约+1 | REQ-B4-003 |
| /orders | POST | 下单支付 | Mock 直接返回成功（暂未实现金额不符分支） | REQ-B5-001 |
| /courses (schedule) | POST | 排课 | 检测教练/时间冲突，冲突则 409 | REQ-B3-001 |
| /risks | GET | 风险清单 | 按 SYS-R7 规则式计算 | REQ-B8-001/002 |
| /commissions | GET | 提成报表 | 课消 40 次 × 20% | REQ-B5-005 |
| /tickets | POST | 提交工单 | **原型未实现提交入口（待改进）** | REQ-B8-007 |

## 三、外部依赖的 Mock 策略

| 外部依赖 | 真实方案 | Mock 方案 |
|---|---|---|
| 微信登录 | code2Session | 直接返回预设会员 |
| 微信支付 | 商户下单 + 回调 | 直接返回支付成功 |
| 订阅消息/短信 | 模板消息 | 控制台日志输出（原型日志区） |

## 四、Mock 使用说明

- 原型为单文件，双击 `index.html` 即可在浏览器打开，无需服务器、无需联网。
- "验证日志"区域实时打印命中的规则/需求编号（如 `SYS-R1`、`REQ-B4-004`），用于核对"业务规则与决策逻辑是否可执行"。
- 点击"重置数据"可恢复初始 Mock 数据，便于重复验证。
