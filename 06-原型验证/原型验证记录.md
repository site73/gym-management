# 原型验证记录

> 所属阶段：第六阶段（UI / API / Mock 原型验证）
> 验证对象：切片 S1（会员·会籍·课程·约课签到）+ S4（流失/爽约预警）
> 原型：`prototype/index.html`（UI 原型 + 内置 Mock 数据 + 规则执行）
> 日期：2026-10-06
> 结果分类：通过 / 不通过 / 待改进

## 一、验证目标

通过 UI、API 与 Mock 数据跑业务流程，验证：角色能否完成业务活动；系统是否正确承接机器应承担的活动；人机协同是否合理；页面/接口/状态是否支持业务流程；异常是否可处理；信息能否在正确角色间流转；业务规则与决策逻辑是否可执行。

**原型不是为了展示页面，而是为了验证当前切片在系统支持下能否真实跑通。**

## 二、验证覆盖

- 主流程：会员约课 → 签到（跨"会员端"与"门店后台"两个端）
- 关键分支：会籍过期拒绝、课程满员拒绝、同时段冲突、取消释放名额
- 关键异常：超时未签到判爽约、爽约累计限制预约、排课冲突、风险评分

## 五、验证方式说明

- UI 原型：验证页面操作与人机协同（会员端/后台两个端）。
- API 原型：验证接口能力与规则执行（Mock 接口按校验顺序返回拒绝原因）。
- Mock 数据：替代未实现的外部依赖（微信登录/支付/消息），保证流程可跑通。
- 三类原型围绕同一业务切片（S1 + S4）组合使用。
