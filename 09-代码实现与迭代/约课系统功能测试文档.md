## 四、缺陷记录与修复

### 4.1 本轮修复的缺陷

| 缺陷编号 | 严重级别 | 现象 | 根因分析 | 修复方案 | 影响范围 |
|---|---|---|---|---|---|
| **BUG-001** | **严重** | 会员端点「取消预约 / 扫码签到 / 模拟超时未签到」**点击无任何反应** | 预约号是字符串（如 `B101`），按钮生成的 `onclick="doCancel(B101)"` **缺少引号**，浏览器把 `B101` 当变量解析 → 抛 `ReferenceError: B101 is not defined`，事件静默失败 | 全部改为带引号：`onclick="doCancel('${b.id}')"` | Node 应用会员端全部预约操作按钮 |
| **BUG-002** | 中 | 点击约课/取消后，会员下拉**跳回第一个会员**，看起来"没有效果" | 操作后调用 `boot()` 重建了 `<select>`，选择被重置 | 拆分 `initPage()`（仅初始化）与 `refreshCourses()`（仅刷课程），刷新不再重建下拉 | Node 应用会员端 |
| **BUG-003** | 中 | 预约状态显示英文 `booked/cancelled`，不易理解 | 后端状态码未做展示映射 | 增加 `STATUS_CN` 映射：已约/已签到/爽约/已取消；签到渠道也中文化 | 两个前端 |
| **BUG-004** | 中 | 重复签到 / 重复取消返回 **500 内部错误** | `BookingEntity` 状态迁移方法抛 `IllegalStateException`，未被处理 | 新增全局异常处理 `ApiExceptionHandler`：状态不允许 → **409 INVALID_STATE**，参数错误 → 400 | 全部接口 |
| **BUG-005** | 中 | 后端管理页**没有预约列表**，无法在后台验证"取消/签到" | 后端只有写接口，缺查询接口与页面入口 | 新增 `GET /api/bookings`（可按会员过滤）+ 管理页「预约列表」（签到/取消/判爽约） | Spring Boot 管理页 |
| **BUG-006** | 低（潜在） | 后端管理页 `onclick` 中 id 未加引号（当前为数字未暴露） | 与 BUG-001 同类问题 | 统一加引号，消除隐患 | Spring Boot 管理页 |

### 4.2 历史缺陷（前序阶段已修复，回归通过）

| 缺陷编号 | 现象 | 根因 | 修复 |
|---|---|---|---|
| BUG-007 | 取消预约后**无法再次预约同一课程** | `booking` 表唯一键 `(member_id, course_id)` 过严 | 新增迁移 `V6__fix_booking_unique_key.sql` 删唯一键改普通索引；幂等改由应用层对 `booked/checked_in/no_show` 判重 |
| BUG-008 | 接口返回中文乱码 | `spring.sql.init` 默认以 GBK 读取 UTF-8 脚本 | 设 `spring.sql.init.encoding: UTF-8` |
| BUG-009 | 健康检查返回 DOWN | 引入 Redis 依赖但本地未启动 | local profile 关闭 Redis 健康检查 |

### 5.3 关键验证点

- **取消链路**：取消 → 余位 +1 → 可再次预约同一课程 → 状态标记 `cancelled`，全链路通过。
- **异常语义**：重复签到/重复取消返回 **409**（而非 500），响应体含 `code=INVALID_STATE`。
- **幂等性**：重复约课返回同一 `bookingId`；重复支付回调不重复续期。
- **数据一致性**：约课/取消后课程余位与 `booking` 记录一致；对账单金额与已支付订单一致。
