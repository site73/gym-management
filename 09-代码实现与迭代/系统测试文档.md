# 健身房运营管理系统 测试文档

> 版本：v2.0（集成版：登录 + 单页 + 全功能合并）
> 被测系统：Spring Boot 3 + MySQL 8.0 后端 + 统一单页前端（登录后按角色进入会员端 / 门店后台）
> 本文档：测试策略、用例设计、缺陷记录、执行结果与复跑方法

## 一、测试策略（六层防护）

| 层次 | 载体 | 关注点 | 数量 |
|---|---|---|---|
| 单元测试 | JUnit 5 + Mockito | 业务规则、权限判定、算法阈值 | 34 |
| 架构守卫 | ArchUnit | 模块边界、依赖方向、Controller 不直连仓储 | 3 |
| 行为驱动验收 | Cucumber（读取 05 目录的 `.feature`） | 关键业务规则可执行 | 18 |
| 集成测试 | `verify/integration-test.js`（真实 HTTP） | 登录、角色权限、全流程 | 45 |
| 前端静态检查 | `verify/frontend-check.js` | 按钮无响应类缺陷（未定义函数 / 无引号 / 元素缺失 / 接口不存在） | 5 |
| 真实浏览器测试 | `verify/browser-test.js`（Playwright + Edge） | 真实点击有响应、无 JS 报错、无 5xx | 32 |

> **"点击无响应"的防护是双保险**：静态检查在提交前拦截（不依赖运行环境），浏览器测试在运行时验证真实交互。

## 四、缺陷记录

### 4.1 集成阶段新发现并修复

| 编号 | 级别 | 现象 | 根因 | 修复 |
|---|---|---|---|---|
| **BUG-010** | **严重** | 后端**第二次启动直接失败**（Cannot start ApplicationContext） | 账号初始化不幂等：重复绑定角色触发主键冲突，被 catch 吞掉但事务已被标记 rollback-only，提交时抛 `UnexpectedRollbackException` | `bindRole` 改为 SQL 层 `insert ... select ... where not exists` 幂等写入；已连续两次重启验证 |
| **BUG-011** | 中 | 浏览器控制台出现 **500** | `/favicon.ico` 不存在，被兜底异常处理当成 500 | 新增 `NoResourceFoundException → 404`；页面加内联空图标避免该请求 |
| **BUG-012** | 中 | 会员端"取消/签到"按钮**点击无反应**（历史遗留） | `onclick="doCancel(${b.id})"` 中字符串预约号未加引号 → `ReferenceError` 静默失败 | 全部改为 `fn('id')`；并新增**静态检查 FE-002/FE-003** 永久防回归 |
| **BUG-013** | 低 | 风险扫描在冷启动首次调用可能出现前端未渲染 | 前端固定 `sleep` 等待不足 + 后端首次调用较慢 | 前端改为轮询等待内容；后端去掉一次重复查询 |
| **BUG-014** | 低 | 自动化测试偶发失败（约 1/3 概率） | 测试用例依赖前一个脚本的数据状态 | 测试开始前先调用管理员接口重置数据，用例自包含 |

### 4.2 历史缺陷（前序阶段，回归通过）

| 编号 | 现象 | 修复 |
|---|---|---|
| BUG-001~006 | 会员端按钮无反应、状态英文、重复操作 500、后台无预约列表等 | 见上一版测试文档（已合入本版 BUG-012 等条目） |
| BUG-007 | 取消后无法再约同一课程 | 迁移 V6 删除 booking 唯一键，幂等改由应用层判重 |
| BUG-008 | 接口中文乱码 | `spring.sql.init.encoding: UTF-8` |
| BUG-009 | 健康检查 DOWN | 本地关闭 Redis 健康检查 |

### 关键验证点

- **认证与权限**：未登录 401；会员越权 403；伪造 memberId 被强制为本人；回调接口免令牌放行（真实支付平台不携带前端令牌）。
- **登录后路由**：会员 → 会员端（无门店标签、无接口日志）；店长 → 门店后台；管理员 → 额外出现"系统管理"。
- **按钮响应**：41 个内联处理器全部指向已定义函数，浏览器实测全部有响应。
- **幂等性**：重复约课 / 重复回调 / 重复启动（账号初始化）均幂等。
- **重启健壮性**：连续两次重启后端均正常启动，账号无重复。
