# 接口契约初步清单

> 所属阶段：第四阶段（目标系统需求分析报告）
> 说明：初步清单，设计阶段细化为正式契约（OpenAPI 或等价文档），并与测试用例同步版本管理。

## 一、外部接口（依赖第三方）

| 编号 | 接口 | 用途 | 协议/方式 | 关键参数 | 关联需求 | 备注 |
|---|---|---|---|---|---|---|
| EXT1 | 微信登录（code2Session） | 小程序会员登录 | HTTPS | code → openid/session_key | REQ-M0-001 | 需小程序主体资质（Q9） |
| EXT2 | 微信支付 | 会籍/课包支付 | HTTPS | 订单号、金额、openid | REQ-B5-001 | 需商户号（Q9） |
| EXT3 | 微信支付回调 | 支付结果通知 | HTTPS 回调 | 交易状态、订单号 | REQ-B5-001、REQ-B5-004 | 需验签与幂等 |
| EXT4 | 小程序订阅消息 | 续费/爽约/课程提醒 | HTTPS | openid、模板ID | REQ-B1-004、REQ-B8-005 | 与短信二选一（Q10） |
| EXT5 | 短信服务 | 兜底提醒 | HTTPS | 手机号、模板 | REQ-B1-004 | 成本与通道待定（Q10） |

## 三、契约示例（约课，片断）

```yaml
POST /bookings
request:
  memberId: string
  courseId: string
response_200:
  bookingId: string
  status: "已约"
response_409:   # 冲突/超额/会籍无效
  code: "BOOKING_REJECTED"
  reason: "会籍过期 | 课程已满 | 时间冲突"
```

## 四、契约要求

- 所有接口须定义鉴权方式、错误码与幂等策略；支付相关接口必须验签且幂等（对齐 REQ-B5-004）。
- 外部接口在原型阶段以 Mock 先行验证（第七阶段），契约文件随代码同版本库管理。
- 接口字段与《目标系统需求分析报告》§8 数据字段、页面字段保持一致。
