# 用户角色与权限说明

> 所属阶段：第四阶段（目标系统需求分析报告）
> 来源：业务角色（会员、会籍顾问、私教、店长、财务、系统管理员）

## 一、系统角色

| 角色 | 端 | 说明 |
|---|---|---|
| 会员 | 小程序 | 仅访问本人数据 |
| 会籍顾问 | Web 后台 | 客户与跟进相关，无财务权限 |
| **教练（私教）** | **独立教练端** | 可登录；仅见**本人课表**、所授课程学员名单，可核销本人课程的签到；不进入门店后台 |
| 店长 | Web 后台 | 全局可见，最高配置权限 |
| 财务 | Web 后台 | 订单/对账/提成查看，无业务修改权 |
| 系统管理员 | Web 后台 | 用户、权限、基础数据、日志 |

> 角色与账号对应关系（演示环境）：`member*` → 会员；`coach*` → 教练；`manager` → 店长；
> `admin` → 系统管理员（店长权限 + 数据重置）。会员亦可通过登录页「注册新会员」自助创建账号（REQ-B1-006）。

## 三、数据权限规则

- **会员**：仅见本人档案、预约、订单、体测。
- **教练（私教）**：仅见**本人课表**与所授课程的学员名单；可核销本人课程的签到；
  对非本人课程的名单与核销请求一律拒绝；不得进入门店后台（排课、场馆维护等接口返回 403）。
- **场地预约**：会员仅见本人的场地预约；门店可见全部并可代客预约/取消。
- **会籍顾问**：可见所负责客户；不可见财务明细与提成金额。
- **财务**：可见订单与对账数据（只读业务），不可修改业务记录。
- **店长**：全局数据可见。
- **管理员**：仅系统配置，默认不可见业务明细（如需要应按最小授权单独开通）。

## 四、权限实现要求

- **REQ-M0-001**：系统应按角色控制功能访问与数据可见范围，所有越权请求应被拒绝并记录。
- 权限变更须留痕（谁、何时、变更了什么）。
- 财务与提成相关数据的查看、导出应记录审计日志（对齐《非功能需求初步说明》合规要求）。
